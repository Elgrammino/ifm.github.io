# IFM 2027 — пробная версия

Статический PWA для просмотра программы. Программа предварительная: её данные нужно подтвердить у организаторов до публичного анонса.

Посетители могут просматривать события и спикеров, добавлять события в избранное, записывать и выгружать личные заметки. Избранное и заметки хранятся только на их устройстве.

## Общие правки

После подключения Firebase Realtime Database новости, добавленные и отменённые события, а также сдвиг расписания доступны всем. При открытии страницы и возврате к ней проверяется общая база; открытая страница проверяет её каждые 20 секунд. Если нет сети, показывается последняя сохранённая программа. Неудачная правка организатора не считается опубликованной.

Редактор открывается шестью нажатиями на карточку организатора. Вход требует учётную запись Firebase Authentication; пароль не содержится в файлах сайта. После обновления страницы организатор входит заново. Право записи задаётся только правилами базы.

## Подключение Firebase

1. В [Firebase Console](https://console.firebase.google.com/) создайте проект IFM. В **Build → Realtime Database** создайте базу в закрытом режиме. Скопируйте её полный адрес с регионом.
2. В **Build → Authentication → Sign-in method** включите **Email/Password**. В **Users** создайте учётную запись организатора и скопируйте её **User UID**. Пароль никому не передавайте и не записывайте в репозиторий.
3. Веб-приложение зарегистрировано; `databaseURL` и `apiKey` уже указаны в `firebase-config.js`. Это публичные параметры подключения.
4. Скопируйте готовый `database.rules.json` в **Realtime Database → Rules** и опубликуйте. Правила открывают чтение только `/s`; запись туда разрешена только учётной записи организатора.
5. Опубликуйте обновлённые файлы сайта. На устройстве организатора войдите через редактор и опубликуйте тестовую новость. На другом устройстве проверьте, что она появилась в течение 20 секунд.

Подключение к базе настроено. Убедитесь, что правила опубликованы и аккаунт организатора создан в Authentication. Не публикуйте правила с записью для всех пользователей.

## Проверка

`node --test tests/*.cjs`

Автоматические проверки покрывают хранение заметок, рендеринг программы, восстановление после ошибок загрузки, офлайн-кеширование, вход, ограничение записи и повтор конкурентной правки. Два физических устройства и реальная база требуют проверки после подключения Firebase.
